# 功能点 07：知识浏览、切片索引与划选批注（从零到一）

> 本篇回答：**入库后的知识条目怎么组织和展示？阅读时的划选高亮怎么存？对话引用怎样沉淀为笔记？**

---

## 1. 这个功能解决什么问题？

知识条目入库后要服务两类场景：

1. **人读**：浏览书架/媒体库/分类，打开条目读全文，划选金句写批注；
2. **机器检索**：对话时要快速找到相关段落——需要把长文切成小段（切片）并建索引。

此外还有一条产品暗线：**对话中 AI 给的引用不该用完即弃**，要能成为用户的知识沉淀——但不能不经确认就混进正式笔记。

## 2. 先修概念

- **RAG 切片（chunking）**：把长文本切成小段（本项目约 500 字），检索时按小段匹配，避免把整本书塞给模型。
- **embedding（向量）**：把文本变成一串数字，语义相近的文本向量距离近。可用余弦相似度度量。
- **字符偏移定位**：用 `start_offset / end_offset` 在原文里标记一段高亮的位置。

## 3. 从零推导

### 第一步：切片——定长滑窗，为什么重叠 80 字

```python
# apps/api/app/modules/knowledge/chunking.py:9-30
def split_text(text: str, *, size: int = CHUNK_SIZE, overlap: int = CHUNK_OVERLAP) -> list[str]:
    raw = (text or "").strip()
    if not raw:
        return []
    overlap = max(0, min(overlap, size - 1))
    chunks: list[str] = []
    start = 0
    n = len(raw)
    while start < n:
        end = min(n, start + size)
        piece = raw[start:end].strip()
        if piece:
            chunks.append(piece)
        if end >= n:
            break
        start = max(0, end - overlap)      # 下一段回退 80 字
        if start >= end:
            start = end                    # 防死循环保护
    return chunks
```

**为什么这样写**：
- **为什么重叠？** 一个知识点可能恰好横跨切片边界（比如结论句落在第 490~510 字）。重叠 80 字保证它在相邻两个切片里都完整出现，检索命中率显著提高。
- **为什么不做"按句子智能切分"？** OCR 文本和 ASR 转写经常没有可靠标点，定长切最稳。残句问题留给展示层的 `expand_to_complete_passage` 补全（见第三步）。
- **embedding 存 JSON 文本**：`chunks.embedding` 是 `Text` 列存 JSON 字符串，不是向量类型——SQLite 没有 vector 类型，为了"本地零依赖"，检索时全量读回内存用纯 Python 算余弦（`core/llm.py` 的 `dump_embedding/load_embedding/cosine_similarity`）。千级切片规模下暴力扫描完全够快，**用架构复杂度换部署零依赖**。

### 第二步：索引重建——幂等与降级

```python
# apps/api/app/modules/knowledge/index.py:41-66（节选）
async def index_entry(db, entry_id, *, with_embed: bool = True) -> int:
    pieces = split_text(text)
    await db.execute(delete(Chunk).where(Chunk.entry_id == entry_id))  # 先删旧
    ...
    if with_embed:
        vectors = []
        batch_size = 16
        for i in range(0, len(pieces), batch_size):   # 分批 16 条
            emb = await embed_texts(db, batch)
            if emb is None:
                vectors = None                        # 降级：切片照存，不带向量
                break
            vectors.extend(emb)
```

**设计解读**：
- **先删后建**：无论正文改了多少次，重建后 chunks 永远反映最新正文——幂等，可反复执行。
- **为什么分批 16 条调 embedding？** 一是很多 embedding API 对批量大小/总 token 有限制；二是任何一批失败就把 vectors 置 None——注意**不是中断，是降级**：切片照常落库，检索时自动走关键词路径。
- `reindex_missing` 用 `NOT IN (SELECT entry_id FROM chunks)` 找漏网条目（服务启动时后台自动跑），`reindex_all` 供切换 embedding 模型后全量刷新。

### 第三步：批注——偏移 + 快照的双保险

```python
# apps/api/app/modules/knowledge/models.py:43-61（节选）
class EntryAnnotation(Base):
    """条目正文划选高亮 / 批注。"""
    entry_id = mapped_column(Integer, ForeignKey("entries.id", ondelete="CASCADE"), index=True)
    start_offset = mapped_column(Integer, default=0)
    end_offset = mapped_column(Integer, default=0)
    quote = mapped_column(Text, default="")
    note = mapped_column(Text, default="")
    # note=用户笔记；chat_anchor=对话预笔记（默认不混入笔记列表，需确认才升级）
    kind = mapped_column(String(20), default="note", index=True)
    color = mapped_column(String(20), default="#facc15")
```

**为什么 offset 和 quote 都要存？** 偏移用于精确跳转定位；quote 是原文快照，用于展示与容错（即使正文重排偏移失效，quote 仍可读）。**冗余不是浪费，是保险。**

**`kind` 字段是产品哲学的 schema 体现**：`note` 是用户正式笔记；`chat_anchor` 是对话自动落的"预笔记"，默认不进笔记列表——**AI 产出物默认草稿态**，用户点"确认"（promote）才转正。

划选不准怎么办？`expand` 端点支持"一次补一句/一行"的微调（前扩/后扩/头缩/尾缩，由 `passage.py` 的 `step_expand/step_shrink` 按句子或行边界走）。关键不变量：**扩缩后必须同步重写 `quote = full[start:end]`**——offset 与 quote 永远一致，下游展示无需二次校验。

### 第四步：对话引用的锚点合并

多轮对话引用同一知识点时，不能每轮都新增一条高亮。`ensure_chat_anchor`（`knowledge/service.py:667-709`）的逻辑：

1. SQL 粗筛 ±120 字内的同 entry 候选锚点；
2. `ranges_same_passage` 精判"是否同一段"（重叠率 ≥45%、短段被包含 ≥60%、或相邻间隙 ≤120 字）；
3. 命中后**长段优先**保留高亮范围，标题用 `merge_point_labels` 合并成「A · B」。

**效果**：一条高亮承载多个对话提及，阅读页始终干净。

"转正"是一次状态迁移：`kind: chat_anchor → note`，顺手做三件事——剥机器前缀、标签变默认笔记名、蓝色换黄色。用户一键确认，AI 草稿变个人资产。判断时还兼容旧数据（历史上用 note 前缀标记而无 kind 字段）——**schema 演进期的向后兼容写法**。

## 4. 完整流程图

```
入库（功能点 06）
   │ index_entry：删旧切片 → split_text(500/80) → 分批 embed(16)
   │   └─ embed 失败 → 切片照存无向量（检索降级关键词）
   ▼
知识浏览：分类 / 书架（book_kind=confirmed）/ 媒体库 / 条目列表
   │
   ├─ 人读：preview 分段读 + 正文内搜索（忽略空白匹配，映射回原文偏移）
   │     └─ 划选 → 批注（offset+quote 双保险，expand 微调，promote/expand/删除）
   │
   └─ 对话引用（功能点 08）→ ensure_chat_anchor 合并落锚点（chat_anchor）
         └─ 用户确认 → promote → 正式笔记（kind=note）
```
