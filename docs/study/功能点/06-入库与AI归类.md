# 功能点 06：入库与 AI 归类（从零到一）

> 本篇回答：**一段抽取好的正文，怎样变成知识库里"有标题、有摘要、有分类、不重复"的正式条目？**

---

## 1. 这个功能解决什么问题？

`ready` 状态的来源只是一坨纯文本。入库（ingest）要做三件事：

1. **起标题、写摘要、分类**——有 AI Key 用 LLM 做，没有也要有兜底；
2. **去重**——同一本书换了个文件名再喂一次，不能产生两个条目；
3. **归类要"干净"**——LLM 或启发式给的分类不能是 "The" "pdf" 这种垃圾词，否则侧栏分类列表会脏掉。

## 2. 先修概念

- **指纹（fingerprint）**：把一段数据归一化后取哈希，用于快速判等。
- **降级（fallback）**：增强路径（LLM）失败时退回保底路径（启发式规则），保证核心功能永远可用。
- **Entry vs Source**：Source 是"喂养来源"（投递记录），Entry 是"知识条目"（入库后的正式资产），一个 Source 入库后对应一个 Entry。

## 3. 从零推导

### 第一步：去重的本质是先定义"什么叫重复"——双指纹

```python
# apps/api/app/modules/sources/classify.py:148-159
def normalize_title_key(title: str) -> str:
    """用于判重的标题指纹：去空白、标点、扩展名。"""
    text = (title or "").strip().lower()
    text = re.sub(r"\.(pdf|epub|txt|md|markdown)$", "", text, flags=re.I)
    text = re.sub(r"[\s_\-–—·・.，,。:：;；!！?？\"'“”‘’（）()【】\[\]《》<>|/\\]+", "", text)
    return text[:200]

def content_fingerprint(text: str) -> str:
    """正文指纹：压缩空白后 SHA256。"""
    compact = re.sub(r"\s+", "", (text or "").strip())
    return hashlib.sha256(compact.encode("utf-8")).hexdigest()
```

**为什么这样设计**：
- 两个指纹互补：`title_key` 抓"同一本书不同文件名"（`被讨厌的勇气.epub` vs `被讨厌的勇气(1).pdf`，归一化后相同）；`content_hash` 抓"不同标题同一内容"（转存改名的电子书）。
- **关键洞察**：去重的核心不是哈希算法，而是**归一化规则定义了什么叫"重复"**——先消除无意义差异（大小写、空白、标点、扩展名），再比较。

### 第二步：四层判重，精确度递减

```python
# apps/api/app/modules/sources/service.py:550-579（节选）
        if content_hash:
            hit = await db.execute(select(Entry).where(Entry.content_hash == content_hash).limit(1))

            if hit.scalar_one_or_none():
                raise HTTPException(status_code=409, detail="相同标题已入库，请勿重复添加")
        # 兼容旧数据：尚未写指纹时，用规范化比较兜底
        legacy = await db.execute(select(Entry.id, Entry.title, Entry.source_id))
        for eid, etitle, esid in legacy.all():
            if title_key and normalize_title_key(etitle or "") == title_key:
                raise HTTPException(status_code=409, detail="相同标题已入库，请勿重复添加")
```

**设计解读**：
- 判重顺序：正文哈希（最强）→ 标题键 → 旧数据规范化兜底 → 同文件名扫描。**第三层是数据迁移期的兼容设计**——指纹字段是后加的，老 Entry 没有，只能现场归一化比对。
- **为什么返回 409 而不是静默跳过？** 让前端能区分"成功入库"与"重复"；批量入库（`ingest-ready`）据此统计 skipped 数量。

### 第三步：LLM 优先、启发式兜底的总开关

```python
# classify.py:317-345（节选）
async def suggest_tags_and_summary(*, title, text, llm):
    """优先 LLM；失败或无 Key 则启发式标签 + 正文截断摘要。"""
    sample = text[:4000]
    fallback_summary = text[:800].rstrip() + ("…" if len(text) > 800 else "")
    fallback_tags = heuristic_tags(title, sample)

    if not llm or not llm.get("api_key"):
        return fallback_tags, fallback_summary
    try:
        tags, summary = await llm_suggest(...)
        if not tags:
            tags = fallback_tags
        if not summary:
            summary = fallback_summary
        return tags, summary
    except Exception:
        return fallback_tags, fallback_summary
```

**这是本项目降级的标准结构**：**先算好兜底结果**，再尝试增强路径，任何环节失败（无 Key、网络错误、LLM 返回空）都落回兜底。保证"入库"这个核心动作永远不依赖 LLM 可用性。注意只取正文前 4000 字送给 LLM——控制 token 成本。

### 第四步：启发式标签——宁可少，不要脏

```python
# classify.py:210-242（节选）
def heuristic_tags(title: str, text_sample: str = "") -> list[str]:
    """无 Key 时：优先中文书名片段 + 关键词映射；不把英文书名切片当分类。"""
    parts = re.split(r"[_\-–—·・|／/]+", title or "")
    for part in parts:
        if not part or not _has_cjk(part):
            continue                    # 只收含中文的片段
        short = re.sub(r"(的)?(哲学课|启示录|导论|入门|讲义|笔记|之父|之母)$", "", part)
        ...
    haystack = f"{title}\n{text_sample[:2000]}"
    for pattern, tag in _KEYWORD_TAGS:  # 如 "阿德勒|adler" → "阿德勒"
        if pattern.search(haystack):
            add(tag)
    return tags[:5] or ["未命名主题"]
```

**设计解读**：
- 两条路：① 标题按 `_-·/` 等分隔符切片，剥掉"的哲学课/之父"这类书名次级尾巴；② 内置关键词正则表映射到固定主题。
- **最关键的约束是 `_has_cjk`**：只收含中文的片段。英文书名切片（The/Forest/and）是分类侧栏最大的污染源——**宁可标签少，也不要脏**。
- `or ["未命名主题"]` 保证永不返回空。

### 第五步：LLM 输出也要过质量门闩

LLM 返回的每个标签都要过 `_clean_tag` / `is_good_tag` 检查：拒绝英文虚词、格式噪声词（pdf/epub）、感叹号口号、含两个以上标点的整句标题。**为什么不信任 LLM？** 因为模型会把花哨的视频标题（"震惊！DeepSeek 又赢了！！"）直接当分类塞进侧栏。所有外部输入——哪怕来自 AI——都要校验。

## 4. 完整流程图

```
POST /ingest（source 须 ready）
        │
        ▼
四层判重：content_hash → title_key → 旧数据规范化 → 同文件名
        │（命中 → 409）
        ▼
suggest_tags_and_summary
   ├─ 有 Key：LLM（前 4000 字）→ 标签过 is_good_tag 门闩
   └─ 无 Key/失败：启发式（中文片段 + 关键词表 → "未命名主题"兜底）
        │
        ▼
创建 Entry（title/summary/title_key/content_hash）+ 分类关联（get_or_create）
        │
        ▼
index_entry 切片 + embedding（功能点 07）
        │
        ▼
source.status = committed（终态）
```
