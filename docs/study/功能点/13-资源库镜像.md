# 功能点 13：本地资源库镜像（从零到一）

> 本篇回答：**`data/uploads/` 里按 id 命名的机器目录，怎样变成 `data/library/书籍/被讨厌的勇气/` 这样人类可读的文件夹？删除时又为什么只删文件夹没用？**

---

## 1. 这个功能解决什么问题？

`uploads/37/` 这种目录人看不懂。用户想在文件管理器里直接看到自己的书、视频、笔记。但镜像带来两个经典问题：

1. **同名冲突**：两本《红楼梦》怎么办？
2. **删除一致性**：数据库、uploads、library 三处数据，删一处不删其余就会出"幽灵资源"。

核心设计原则一句话：**Source 表是唯一事实，library 只是可随时重建的缓存视图。**

## 2. 从零推导

### 第一步：投影——机器类型翻译成中文目录

```python
# apps/api/app/modules/library/service.py:28-34
CATEGORY_MAP: dict[str, tuple[str, str]] = {
    "ebook": ("books", "书籍"),

    "url": ("web", "网页"),
```

同步主流程（`service.py:190-242` 节选）：

```python
def sync_source_files(*, source_id, source_type, title) -> Path | None:
    """把 uploads/{id} 同步到 library/{分类}/{标题}/。"""
    upload = _data_root() / "uploads" / str(source_id)
    files = _collect_upload_files(upload)
    if not files:
        remove_source_from_library(source_id)
        return None
    folder_name = safe_folder_name(display_title, source_id)
    # 同名但属于别的来源：加 id 后缀
    if dest.exists():
        other_id = 读 dest/.kongku-source.json 里的 source_id
        if other_id not in (None, 0, source_id):
            dest = cat_dir / f"{folder_name} ({source_id})"
    for src, friendly in files:
        _link_or_copy(src, dest / friendly)     # 硬链 → 符号链 → 复制
    _write_meta(dest, source_id, display_title, source_type)
```

**设计解读**：
- **双层翻译**：类型 → 中文目录（ebook→书籍）；内部文件名再经 `FRIENDLY_NAMES` 翻译（extracted.txt → 正文.txt）——用户打开文件夹看到的是人话。
- **归属锚点**：每个镜像文件夹里写隐藏文件 `.kongku-source.json`（存 source_id/title/type）。同名撞车时读 meta 比对 id，属于别人就加 `(37)` 后缀——**不靠猜，靠凭证**。
- **三级落文件策略** `_link_or_copy`：硬链（同盘零空间）→ 符号链 → 复制（跨盘兜底），按可用性降级。

### 第二步：重建——为什么"笔记库"绝不能碰

```python
# service.py:320-349（节选）
async def rebuild(self, db) -> LibraryRebuildOut:
    root = library_root()
    for child in list(root.iterdir()):
        # 手写笔记树与资源根同处，重建时绝不能清空
        if child.name == VAULT_CATEGORY_DIR:   # "笔记库"
            continue
        shutil.rmtree(child, ignore_errors=True) if child.is_dir() else child.unlink()
    for row in select(Source).order_by(Source.id):
        if (row.vault_path or "").strip():
            continue                            # 笔记不做镜像（避免一篇笔记两处出现）
        sync_source_files(...)
```

**这是全项目"数据分层"最清晰的表达**：文件系统分两类——**原始数据**（uploads、笔记库 .md，用户数据的真身）与**投影缓存**（library 镜像，可丢可重建）。rebuild 清掉所有镜像再按 Source 表重新生成；笔记库是原始数据，`continue` 硬跳过。

### 第三步：删除的四层联动

```python
# service.py:275-318（节选）
async def delete_item(self, db, source_id: int):
    """真正删除资源：喂养来源 + 已入库条目 + uploads + library 镜像。
    注意：只删 data/library 下的文件夹不会生效——重建会按来源再生成。"""
    entries = await db.execute(select(Entry).where(Entry.source_id == source_id))
    for entry in entries.scalars().all():
        await sources_service._remove_entry_tree(db, entry)   # ① Entry+切片+分类关联
    await db.delete(row)                                      # ② Source 行
    await db.commit()
    shutil.rmtree(upload, ignore_errors=True)                 # ③ uploads/{id}
    if vault_rel and row.type == "note":                      # ④ 笔记才删 vault 文件
        vpath.unlink(missing_ok=True)
    remove_source_from_library(sid)                           # ⑤ library 镜像
```

**三个教学细节**：
1. **docstring 直面用户困惑**："只删文件夹不会生效"——因为重建会按 Source 表把镜像再生成。想永久删除必须走 API（前端 `DELETE /api/library/items/{source_id}`）。
2. **顺序讲究**：先 commit 数据库再清文件——即使文件清理失败，重建也不会把幽灵资源还原。
3. **防御性 `row.type == "note"` 双重确认**：注释记录了历史教训——SQLite 复用自增 id 时，曾误删同 id 残留的书籍文件夹。
4. **函数内延迟 import** `sources_service`：打破 library ↔ sources 的循环依赖。

## 3. 完整流程图

```
喂养/入库（任何来源）
   │ sync_source：uploads/{id} → library/{中文分类}/{标题}/
   │   ├─ 同名撞车 → 读 .kongku-source.json 比对 id → 加 (id) 后缀
   │   └─ 落文件：硬链 → 符号链 → 复制
   ▼
data/library/
   ├─ 书籍/ 视频/ 网页/ 笔记/   ← 投影缓存（可 rebuild 重建）
   └─ 笔记库/                   ← 原始数据（vault，rebuild 跳过）
   ▼
DELETE /api/library/items/{id}
   └─ Entry 树 → Source → uploads → (note?vault文件) → library 镜像，五层联动
```
