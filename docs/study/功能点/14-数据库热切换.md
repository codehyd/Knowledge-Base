# 功能点 14：数据库配置与热切换（从零到一）

> 本篇回答：**默认 SQLite 零依赖，但用户想换自己的 PostgreSQL——怎样做到不重启服务就换库？换库配置本身又存在哪里？**

---

## 1. 这个功能解决什么问题？

三个层层递进的问题：

1. **鸡生蛋问题**：如果"用哪个数据库"这个配置存在数据库里——那读配置之前就连不上库。配置必须放在库外；
2. **改配置要重启吗？** 用户在设置页点了"切换"，要求立即生效，不能重启进程；
3. **老库升级怎么办？** 新版本加了字段，老用户的 .db 文件不能打不開——需要无感知的列迁移。

## 2. 先修概念

- **连接串（DSN）**：如 `sqlite+aiosqlite:///data/kongku.db`、`postgresql+asyncpg://user:pass@host/db`，一个字符串说清"什么库、在哪、怎么连"。
- **热切换**：进程不退出，替换数据库引擎对象，后续请求走新连接。
- **幂等迁移**：迁移脚本跑一遍和跑十遍效果一样（"缺列才补"），不怕重复执行。

## 3. 从零推导

### 第一步：配置放库外——三级优先级

`apps/api/app/core/runtime_db.py` 文件头一句话点破设计动机：

```python
"""业务库连接配置（落在 DB 外，避免鸡生蛋问题）。
优先级：data/runtime-db.json → 环境变量 DATABASE_URL → 默认 SQLite。
"""

def resolve_database_url() -> str:
    cfg = load_runtime_config()          # data/runtime-db.json
    if cfg is not None:
        return url_from_runtime(cfg)
    env_url = (get_settings().database_url or "").strip()
    if env_url:
        return normalize_postgres_url(env_url)
    return sqlite_url_for_path(default_sqlite_path())
```

**为什么 runtime-db.json 优先级高于环境变量？** 用户在 UI 上切换数据库后写入这个文件，要**立即生效**；而环境变量是进程启动时的快照，改不了。三级回落保证任何情况下都有可用默认值（开箱即 SQLite）。

配套的两个"宽容"函数：
- `normalize_postgres_url`：用户从云控制台复制的连接串协议头五花八门（`postgres://` 是 Heroku 遗风），统一改写成 `postgresql+asyncpg://` 方言；
- `mask_database_url`：回显时脱敏密码——主路径用 `urlparse` 精确重建，异常时正则兜底。**脱敏不允许失败到泄密：宁可脱错，不可不脱。**

SQLite 路径的坑（`resolve_sqlite_path`）：相对路径相对的是**进程 cwd**，而 cwd 不可控（IDE/uvicorn/sidecar 各不相同）。所以相对路径一律相对 `DATA_DIR` 解析，还专门兼容历史遗留值 `data/kongku.db`——**配置永不弄丢用户数据**。

### 第二步：热切换——全局引擎替换

```python
# apps/api/app/core/database.py:33-53（节选）
engine: AsyncEngine | None = None
SessionLocal: async_sessionmaker[AsyncSession] | None = None

def configure_engine(url: str) -> AsyncEngine:
    """创建（或替换引用前）引擎；不负责 dispose 旧引擎。"""
    global engine, SessionLocal
    kwargs = {"pool_pre_ping": True}
    if url.startswith("sqlite"):
        from sqlalchemy.pool import NullPool
        kwargs["poolclass"] = NullPool
    engine = create_async_engine(url, **kwargs)
    SessionLocal = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)
```

**设计解读**：
- 模块级全局变量持有引擎——替换引用后，所有 `get_db` 之后的新请求自然走新引擎。docstring 划清职责："不负责 dispose 旧引擎"（那是 reconnect 的事）。
- `pool_pre_ping=True`：防连接池里的死连接（数据库重启过的话）。
- **SQLite 强制 NullPool**：文件库不需要长连接池，且避免多连接写锁竞争。
- 这也是为什么所有后台任务（功能点 03/08）都"每次动态取 SessionLocal"——缓存旧工厂就会写到旧库。

### 第三步：三个端点，副作用边界清晰

```python
# apps/api/app/modules/settings_db/router.py:25-68（节选）
@router.put("", summary="保存并切换数据库",
    description="校验连通性后写入 runtime-db.json 并热切换。SQLite 自动建表；Postgres 仅切换连接，需再调用「初始化表结构」。")

@router.post("/test", summary="测试数据库连通性",
    description="只试连，不切换、不建表、不落盘。")

@router.post("/init", summary="初始化 / 对齐表结构",
    description="对当前已连接数据库执行 create_all 与轻量列迁移…Postgres 建议在切换连接后由用户点击触发。")
```

**为什么拆成三个？** 把"改配置"拆成幂等、副作用明确的动作：`/test` 连用四个否定（不切换、不建表、不落盘）承诺纯探测；`PUT` 先校验再落盘再热切换；`/init` 独立存在因为**对远程库建表是危险操作**，必须用户显式点击——与功能点 01 里 lifespan"Postgres 只探测"的策略首尾呼应。错误区分 `ValueError`（用户输入 → 400）与其它（基础设施 → 500），`from exc` 保留异常链。

### 第四步：免 Alembic 的"穷人版"列迁移

```python
# database.py:136-150（节选）
async def _add_column_if_missing(conn, table: str, column: str, ddl_type: str) -> None:
    cols = await _table_columns(conn, table)
    if column in cols:
        return
    await conn.execute(text(f"ALTER TABLE {table} ADD COLUMN {column} {ddl_type}"))
```

**为什么不引入 Alembic？** 个人项目的务实替代：先查表结构、缺列才 ALTER，幂等可重跑、零依赖、启动即自愈。配套的 `_ensure_*_columns` 系列还夹带存量数据回填 UPDATE——schema 迁移 + 数据迁移合一。

启动时 Postgres 会尝试 `CREATE EXTENSION IF NOT EXISTS vector`（pgvector），**装不上就降级**（`set_vector_enabled(False)`），检索走纯 Python 余弦——能力探测 + 优雅降级的又一例。

## 4. 完整流程图

```
设置页填连接串
   ├─ POST /api/settings/db/test → 只试连（不落盘）
   ├─ PUT /api/settings/db → 校验 → 写 data/runtime-db.json → reconnect 热切换
   │     ├─ SQLite → 自动 init_db（建表+列迁移+种子行）
   │     └─ Postgres → 只切连接
   └─（Postgres）POST /init → create_all + 列迁移 + 尝试 pgvector 扩展
   ▼
resolve_database_url 优先级：runtime-db.json > DATABASE_URL > 默认 SQLite
```

## 5. 关键文件与配置对照

| 文件 | 职责 |
|------|------|
| `apps/api/app/core/runtime_db.py` | 三级解析、URL 规范化/脱敏、SQLite 路径解析 |
| `apps/api/app/core/database.py` | 引擎全局管理、init_db、幂等列迁移 |
| `apps/api/app/modules/settings_db/router.py` | 读/切/试连/初始化四端点 |
| `apps/api/app/core/capabilities.py` | pgvector 能力探测 |
| `data/runtime-db.json` | 运行时数据库配置（优先级最高） |

| 配置 | 说明 |
|------|------|
| `DATABASE_URL`（.env） | 兜底连接串；桌面端默认强制指向 userData 下的 SQLite（`KONGKU_USE_ENV_DB=1` 解除） |
| `KONGKU_USE_ENV_DB=1` | 桌面端允许系统环境变量指定数据库 |

**注意**：SQLite 与 Postgres 两套库之间不自动同步数据，切换前先用 `/test` 确认连通，旧数据需自行导出迁移。
