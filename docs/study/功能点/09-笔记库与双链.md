# 功能点 09：笔记库 Vault 与双链（从零到一）

> 本篇回答：**怎样在应用内做一个 Obsidian 式的 Markdown 笔记系统——文件直接落盘、保存即参与问答、`[[双链]]` 串成知识网络？**

---

## 1. 这个功能解决什么问题？

喂养来的知识是"读别人的"，笔记是"写自己的"。笔记库要满足：

1. **笔记是普通 .md 文件**，存在磁盘上可以直接用别的编辑器打开（不被应用绑架）；
2. **保存即入库**——写完的笔记立刻可以被对话检索到；
3. **支持 `[[双链]]`**，笔记之间互相引用，并能画出关系图；
4. **路径安全**——前端传来的文件路径绝不能越出笔记目录（防 `../../etc/passwd` 这类攻击）。

## 2. 先修概念

- **Vault**：Obsidian 的概念，指"一整个文件夹的 Markdown 笔记"。本项目 vault 物理位置是 `data/library/笔记库/`。
- **双链（wikilink）**：`[[笔记名]]` 语法，A 笔记里写 `[[B]]` 就建立 A→B 的链接；还支持 `[[B|别名]]` 和 `[[B#章节]]`。
- **路径穿越攻击**：用户传 `../../../Windows/system.ini` 这种路径读写系统文件，服务端必须拦截。

## 3. 从零推导

### 第一步：文件系统当后端的安全基石——三道关卡

```python
# apps/api/app/modules/vault/paths.py:90-134（节选）
def normalize_rel(path: str) -> str:
    raw = (path or "").replace("\\", "/").strip().lstrip("/")
    parts: list[str] = []
    for part in raw.split("/"):
        if not part or part == ".":
            continue
        if part == "..":
            raise HTTPException(status_code=400, detail="非法路径")   # 关卡 1
        parts.append(safe_segment(part))                              # 关卡 2
    return "/".join(parts)

def resolve_in_vault(rel: str) -> Path:
    root = vault_root()
    target = (root / normalize_rel(rel)).resolve() if norm else root
    try:
        target.relative_to(root)                                      # 关卡 3
    except ValueError as exc:
        raise HTTPException(status_code=400, detail="路径越界") from exc
    return target
```

**为什么需要三道而不是一道**：
1. `..` 直接 400——挡住显式上跳；
2. 每段过 `safe_segment` 剥离非法字符——挡住脏文件名；
3. `resolve()` 后用 `relative_to(root)` 做最终判定——**挡住符号链接逃逸**（假设 vault 里有个指向 `/etc` 的软链，前两关都发现不了，只有解析后的真实路径比对能抓到）。安全设计要假设每一道都可能被绕过。

### 第二步：保存即入库——一次 Ctrl+S 背后的四件事

```python
# apps/api/app/modules/vault/service.py:271-324（节选）
async def _auto_commit(self, db, row: Source, text: str) -> None:
    """保存后自动入库或重切片（不做 LLM 归类，固定「笔记库」标签）。"""
    digest = content_fingerprint(text)
    entry = ... 按 source_id 查 ...
    if entry is None:
        entry = Entry(title=title, summary=text[:SUMMARY_CHARS], ...)
        db.add(entry)
    else:
        entry.title = title
        entry.content_hash = digest
        ...
    # 手写笔记固定只挂「笔记库」分类，避免误挂书籍等标签造成知识页错乱
    cat = await self._ensure_category(db, "笔记库")
    ...
    row.status = "committed"
    try:
        await index_entry(db, entry.id, with_embed=True)   # 重新切片 + 向量化
    except Exception:
        pass
```

**设计解读**：
- 保存时四件事：写 .md 文件 → 更新 Source 行 → upsert Entry（有则改无则建）→ `index_entry` 重切片。笔记立刻可被对话检索。
- **为什么不做 LLM 归类？** 手写笔记的内容是用户自己定的，先删掉非"笔记库"的旧分类再挂固定分类——把 AI 的不确定性挡在自动流程之外。
- **索引失败 try/except pass**：保证"文件保存成功"这个核心承诺不被索引故障破坏——笔记先落盘，索引可以稍后自愈（`reindex_missing` 启动时会补）。

### 第三步：双链解析——一个正则吃三种语法

```python
# apps/api/app/modules/vault/wikilink.py:9-32（节选）
_WIKILINK_RE = re.compile(r"\[\[([^\]\n]+?)\]\]")

def split_note_heading(target: str) -> tuple[str, str | None]:
    """[[笔记#一级#二级]] → note, '一级#二级'。"""
    t = (target or "").strip()
    if "|" in t:
        t = t.split("|", 1)[0].strip()     # 先去别名
    if "#" not in t:
        return t, None
    note, _, heading = t.partition("#")     # 再切锚点
    ...
```

解析目标时用**三级索引降级匹配**（`resolve_wikilink`）：完整相对路径 → 文件名 stem → 标题（全部小写比较）。**为什么三级？** 用户随手写 `[[红楼梦]]` 不会记得完整路径——路径最精确先试，文件名次之，标题兜底。"用户随手写也能命中"的体验就是这么来的。`by_stem/by_title` 索引只收唯一值：**重名时宁可不连，也不乱连**。

### 第四步：关系图——一篇笔记不能出现两个节点

`/graph` 端点合成节点时最大的陷阱：一篇 vault 笔记**既是磁盘 .md 文件、又是已入库的 Entry**，会重复出现。解法（`vault/service.py:711-775` 节选）：

```python
    node_id = f"note:{rel}"        # 命名空间化 id
    note_id_by_vault[rel] = node_id
    ...
    # 处理 Entry 时：已有笔记节点 → 不建新节点，只合并 entry_id 与正文扫描
    if vault_rel and vault_rel in note_id_by_vault:
        nid = note_id_by_vault[vault_rel]
        ...
        continue
```

**设计解读**：节点 id 带命名空间（`note:{路径}`、`entry:{id}`、`cat:{分类名}`），用 `note_id_by_vault` 映射去重。边分两类：`wikilink`（双链，含 `resolved=False` 的断链——指向还不存在的笔记，前端可提示"点击创建"）和 `in_category`（条目→分类枢纽）。

### 第五步：编辑器侧——双链是纯文本，不是特殊节点

前端 TipTap 编辑器里（`apps/web/src/shared/ui/markdown-editor/`）：

- 双链选择**纯文本 `[[target]]`** 而不是自定义 node——图谱解析依赖字面文本，导出 Markdown 零损耗；编辑器内用 ProseMirror `Decoration.inline` 只加 CSS 高亮，**不改文档结构**（表现层与数据层分离）。
- 导出前 `restoreWikilinkMarkers` 反转义（TipTap 会把 `[` 序列化成 `\[`）。
- Slash 命令的触发文本读取：ProseMirror 没有"光标前文本"现成 API，要 `doc.resolve(from)` → `textBetween` 取文本块内光标前内容，正则锚定 `/xxx`；执行命令前先删掉触发文本再应用格式，否则标题里会残留 `/h1`。

## 4. 完整流程图

```
用户在编辑器写笔记（TipTap / 语雀编辑器，[[双链]] 纯文本 + 高亮装饰）
        │ Ctrl+S
        ▼
PUT /api/vault/notes/{source_id}
        │ resolve_in_vault 三道关卡校验路径
        ├─ 写 data/library/笔记库/**.md（语雀编辑器另有 .lake 源文件）
        ├─ _auto_commit：upsert Entry（固定「笔记库」分类）
        └─ index_entry 重切片（失败 pass，启动时自愈）
        ▼
GET /api/vault/graph
        │ 扫全部 .md 正则提双链 → 三级解析 → note/entry/cat 节点 + wikilink/in_category 边
        ▼
前端关系图（断链单独列出，可点击创建）
```
