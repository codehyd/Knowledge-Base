# 功能点 01：应用骨架与启动（从零到一）

> 本篇回答一个问题：**一个 FastAPI 后端，怎样从零组装成「空库」这样可桌面、可网页、可断库自愈的服务？**

---

## 1. 这个功能解决什么问题？

假设你要写一个后端，最朴素的写法是：

```python
app = FastAPI()

@app.get("/api/entries")
def list_entries(): ...
```

几十行业务后你会遇到四个真实问题：

1. **所有代码挤在一个文件里**，功能多了无法维护；
2. **启动时数据库没连上，整个服务直接崩**，用户连"去设置页修配置"的机会都没有；
3. **前端在浏览器、Electron 两种宿主里跑，跨域（CORS）各种报错**；
4. **启动时要建索引、打模型，把 `/health` 健康检查也拖死**。

「空库」的应用骨架就是为解决这四件事而设计的。

## 2. 先修概念

- **应用工厂（Application Factory）**：不直接写 `app = FastAPI()`，而是写一个 `create_app()` 函数返回 app。好处：测试可以建多个互不影响的实例；桌面端 sidecar 和开发态各自拿干净的 app。
- **lifespan**：FastAPI 的启动/关闭钩子。`yield` 之前的代码在服务启动时跑，之后的在关闭时跑。
- **中间件（Middleware）**：套在请求处理外层的"洋葱皮"，CORS、缓存头都在这里做。
- **CORS 预检（OPTIONS）**：浏览器跨域请求前先发一个 OPTIONS 探路，响应头里没带允许的来源，请求直接失败（典型报错 `Failed to fetch`）。

## 3. 从零推导

### 第一步：模块化路由——新功能只加一行

文件头部注释写明了分层契约：

```python
"""空库 API 入口：只负责组装各功能模块路由，不含业务逻辑。"""
```

组装方式（`apps/api/app/main.py:74-130` 节选）：

```python
def create_app() -> FastAPI:
    settings = get_settings()
    app = FastAPI(
        title="空库 API",
        version="0.1.0",
        lifespan=lifespan,
        docs_url=None,      # 关掉自带 Swagger
        redoc_url=None,     # 关掉自带 ReDoc
    )
    # ... CORS ...
    app.include_router(health.router)                    # 无前缀
    app.include_router(sources.router, prefix="/api")    # 其余统一 /api
    app.include_router(chat.router, prefix="/api")
    # ...
```

**每段的作用与原因**：
- `create_app()` 用工厂而非全局实例：桌面端打包后是 PyInstaller sidecar 进程、开发时是 uvicorn、测试时是 TestClient，三种场景各自调用工厂拿到独立实例，互不污染。
- `docs_url=None, redoc_url=None`：主动关闭 FastAPI 自带的两套文档页面，把入口让给自建的 Knife4j（`/doc.html`）。**为什么？** 两套文档并存会让用户困惑"到底看哪个"，产品上只保留一个入口。
- 每挂一个模块就一行 `include_router`，注释写着"后续新功能只加一行"——**这是给未来的自己降低接入成本**：新功能 = 新模块目录 + 一行注册。

### 第二步：CORS——面向真实故障史的配置

```python
    # 本机优先：Electron loadFile → Origin "null"；Vite 开发页 41779；
    # 手动起 API 时也要放行，否则桌面端 / 跨端口会 OPTIONS 400 → Failed to fetch
    origins = list(settings.cors_origins)
    for extra in ("null", "file://", "http://127.0.0.1:41779", ...):
        if extra not in origins:
            origins.append(extra)
    app.add_middleware(
        CORSMiddleware,
        allow_origins=origins,
        allow_credentials=True,
        allow_methods=["*"],
        allow_headers=["*"],
        expose_headers=["Content-Disposition", "X-Kongku-Filename"],
        allow_origin_regex=r"^https?://(localhost|127\.0\.0\.1)(:\d+)?$",
    )
```

**为什么这样写**（这段注释本身就是踩坑记录）：
- **Origin `"null"`**：Electron 用 `loadFile` 从 `file://` 加载页面时，浏览器把 Origin 置为字面量 `"null"`。不放行它，桌面端所有请求都会 OPTIONS 400。这是桌面应用才有的坑，纯 Web 项目永远遇不到。
- **`allow_origin_regex` 兜底任意 localhost 端口**：这是"本机工具"定位下的取舍——用户可能改端口、可能开多个调试实例，用正则放行所有本机端口，省去来回改配置。
- **`expose_headers`**：公版书"另存为"时，前端要从响应头读文件名（`Content-Disposition` / `X-Kongku-Filename`）。CORS 默认不暴露自定义响应头，必须显式列出，否则前端 JS 读不到。

### 第三步：lifespan——断库也要能起来

```python
@asynccontextmanager
async def lifespan(_: FastAPI):
    # SQLite：启动时自动建表对齐；Postgres：只探测，表结构由设置页「初始化」按钮触发
    try:
        mode = detect_mode_from_url(resolve_database_url())
        if mode == "sqlite":
            result = await init_db()
            print(f"[kongku] init_db ok (sqlite): {result.get('message')}")
        else:
            status = await db_mod.schema_status()
            print(f"[kongku] postgres connected={status.get('connected')} ...")
    except Exception as exc:
        print(f"[kongku] init_db skipped (database unavailable or failed): {exc}")
```

**设计决策解读**：
- **SQLite 自动建表，Postgres 只探测不动手**：本地文件库是零配置场景，直接自动建表；远程库是用户的生产资产，应用启动时擅自改 schema 是不可接受的，所以建表动作留给设置页的「初始化」按钮显式触发。
- **整个块被 try/except 包住，只打印不抛错**：这是"自愈型工具"的核心——数据库挂了 API 也要起来。如果启动就崩，用户连设置页都打不开，永远修不好配置。**先能开门，再谈干活。**
- 随后的索引补建用 `asyncio.create_task` 放后台，注释说明原因：`with_embed 会打模型，同步跑会拖死启动 /health`。先让服务可响应，索引慢慢补。

### 第四步：桌面端静态托管——同源消灭跨域

```python
    web_dir = os.environ.get("KONGKU_WEB_DIR", "").strip()
    if web_dir:
        web_path = Path(web_dir)
        if web_path.is_dir():
            class WebCacheControlMiddleware(BaseHTTPMiddleware):
                """避免 Electron 对固定 localhost 前端强缓存导致升级后仍是旧界面。
                - HTML / 入口：no-store（每次拿最新 index）
                - /assets/* 带 hash：可长期缓存
                - 其余静态：短缓存且必须再验证
                """
```

**为什么这样写**：
- **为什么用环境变量而不是配置字段？** 这个值是 Electron 打包器在启动 sidecar 时动态注入的（前端构建产物在 `resources/web`），它不属于"用户配置"，属于"运行时装配"。
- **为什么让 API 托管前端？** 打包态如果用 `file://` 加载前端，所有 API 请求都是跨域的（第三步的 `"null"` Origin 问题）；让 API 同源托管后，前端请求同域，CORS 问题从根上消失。
- **三级缓存策略**是 SPA 的教科书写法：HTML 永远 `no-store`（解决"升级后还是旧界面"的真实 bug）、带内容 hash 的 `/assets/*` 给一年 immutable（内容变 hash 变，放心缓存）、其余短缓存。

## 4. 配置加载：从 `__file__` 反推 `.env`

```python
def _env_files() -> tuple[str, ...]:
    """兼容从仓库根或 apps/api 启动。"""
    here = Path(__file__).resolve()
    api_dir = here.parents[2]  # apps/api
    repo_root = here.parents[3]
    candidates = [api_dir / ".env", repo_root / ".env", Path(".env")]
    existing = [str(p) for p in candidates if p.is_file()]
    return tuple(existing) if existing else (".env",)
```

**为什么不从 cwd（当前工作目录）找 `.env`？** 因为启动目录不可控：IDE 里运行、uvicorn --reload、打包后的 sidecar，三者的 cwd 各不相同。从代码文件自己的位置反推，永远找得到。返回"存在的文件列表"而非单一文件，让仓库根和 apps/api 的 .env 可以叠加生效。

配置字段设计同样贯彻"零配置开箱"（`core/config.py:24-42`）：敏感字段默认空串，地址字段带安全默认（DeepSeek 模板），`database_url` 故意可空——空则回落到默认 SQLite。CORS 用逗号字符串存（环境变量友好）再用 `@property` 转 list，因为 pydantic-settings 解析 list 类型环境变量要求 JSON 格式，字符串+属性是更宽容的写法。

## 5. 完整流程图

```
uvicorn / sidecar 启动
      │
      ▼
create_app() ─────────────────────────────┐
      │                                    │
      ├─ FastAPI 实例（关自带 docs）        │
      ├─ CORS 中间件（null/file:// 放行）   │
      ├─ lifespan 启动：                    │
      │    ├─ resolve_database_url()       │
      │    ├─ SQLite → init_db() 建表       │
      │    ├─ Postgres → 只探测不建表       │
      │    ├─ 全程 try/except：断库也启动   │
      │    └─ 后台 task 补建切片索引         │
      ├─ 挂载 11 个模块路由（/api 前缀）     │
      └─ KONGKU_WEB_DIR 存在？              │
           └─ 是 → 缓存中间件 + 托管前端 ←──┘
```
