# 功能点 04：内容解析抽取（从零到一）

> 本篇回答：**电子书（EPUB/TXT/PDF，含扫描件）和网页，怎样统一变成一段干净的纯文本？**

---

## 1. 这个功能解决什么问题？

喂养进来的资料格式五花八门：记事本存的 GBK 编码 txt、带复杂排版的 PDF、手机扫描的 PDF（一页就是一张图）、EPUB 电子书、满是广告和导航栏的网页。而下游（预览、搜索、切片、对话检索）只需要一样东西：**纯文本**。

难点在于：
1. 每种格式的"抽文本"方法完全不同；
2. 每种方法都有搞不定的情况（pypdf 对扫描件返回空串、网页正文被广告淹没）；
3. 重依赖（OCR 引擎、PDF 库）缺了不能把整个服务搞挂。

## 2. 先修概念

- **文字层 vs 扫描件**：电子版 PDF 内部存着文字编码（可选中复制），扫描版 PDF 每页是一张图片——前者抽文字层即可，后者必须 OCR。
- **OCR（光学字符识别）**：把图片里的文字识别成文本。本项目用 RapidOCR（中英，基于 onnxruntime）。
- **EPUB 的本质**：一个 zip 包，里面是一堆 XHTML 文件——解 zip + 去 HTML 标签就是正文。
- **trafilatura**：专门的网页正文抽取库，能识别并剔除导航、广告、页脚。

## 3. 从零推导

### 第一步：多入口、单产物——最重要的架构决策

`process_extract` 的收口（`sources/service.py:863-884`）：

```python
            folder = _data_root() / "uploads" / str(row.id)
            text_file = folder / "extracted.txt"
            text_file.write_text(text, encoding="utf-8")
            row.text_path = str(text_file.relative_to(_data_root())).replace("\\", "/")
            row.char_count = len(text)
            row.status = "ready"
```

**设计解读**：无论来源是 EPUB、扫描 PDF 还是网页，经过多么不同的解析路径，最终都收敛到同一个产物：`uploads/{id}/extracted.txt`。**"多入口、单产物"是整条流水线最重要的决策**——下游的预览、搜索、入库、切片只面对一个 txt 文件，完全不关心它来自哪种格式。新增一种格式时，只需加一个抽取函数，下游零改动。

### 第二步：TXT——编码探测是第一道关

```python
# apps/api/app/modules/sources/extractors.py:39-49
def decode_bytes(data: bytes) -> str:
    for enc in ("utf-8", "utf-8-sig", "gbk", "gb18030"):
        try:
            return data.decode(enc)
        except UnicodeDecodeError:
            continue
    return data.decode("utf-8", errors="ignore")
```

**为什么这样写**：中文用户的 txt 来源极其混乱——Linux/Mac 多是 UTF-8，Windows 记事本默认存 GBK，有些带 BOM（utf-8-sig）。按 `utf-8 → utf-8-sig → gbk → gb18030` 顺序试错覆盖全部主流情况；最后 `errors="ignore"` 兜底，**宁可丢几个乱码字，也不抛错让整个投递失败**。

### 第三步：EPUB——25 行自写解析器，不引重依赖

```python
# extractors.py:12-36
class _HTMLTextExtractor(HTMLParser):
    def handle_starttag(self, tag, attrs):
        if tag in {"script", "style", "noscript"}:
            self._skip = True

    def handle_endtag(self, tag):
        if tag in {"script", "style", "noscript"}:
            self._skip = False
        if tag in {"p", "div", "br", "li", "h1", "h2", "h3", "tr"}:
            self._chunks.append("\n")

    def handle_data(self, data):
        if not self._skip and data:
            self._chunks.append(data)
```

```python
# extractors.py:161-177
def extract_epub(path: Path) -> str:
    from ebooklib import epub
    from ebooklib import ITEM_DOCUMENT
    book = epub.read_epub(str(path))

    for item in book.get_items_of_type(ITEM_DOCUMENT):

        parser = _HTMLTextExtractor()
        parser.feed(html)

```

**设计解读**：
- **分工**：ebooklib 负责解 zip 拿到各章节 XHTML，标准库 `HTMLParser` 负责去标签。刻意不引入 BeautifulSoup 这类重依赖——解析 HTML 只需"跳过 script/style、块级标签换行、收文本"三件事，25 行够用。
- **复用**：这个 `_HTMLTextExtractor` 同时服务 EPUB 和网页兜底路径，一次投资两处收益。
- **最后防线**：抽完不足 20 字符抛 `ValueError("EPUB 未能抽出有效正文")`——宁可明确失败进 `failed` 状态，也不让空文本混进知识库。

### 第四步：PDF——三级回退，用"产出够不够"做裁判

```python
# extractors.py:132-158
def extract_pdf(path: Path) -> str:
    """优先抽文字层；不足时再 RapidOCR（适合扫描版 PDF）。"""
    text = ""
    try:
        text = _extract_pdf_pypdf(path)
    except Exception:
        text = ""
    if len(text) >= _MIN_TEXT_CHARS:   # 20
        return text

    try:
        text = _extract_pdf_pymupdf_text(path)
    except Exception:
        text = ""
    if len(text) >= _MIN_TEXT_CHARS:
        return text

    try:
        return _ocr_pdf_pages(path)
    except Exception as exc:
        raise ValueError(f"扫描版 PDF 识别失败：{exc}。请确认已安装 rapidocr / onnxruntime...") from exc
```

**为什么这样设计**：
- **回退顺序 = 成本递增、能力递增**：pypdf 最快但弱；pymupdf（fitz）文字层更强；OCR 慢 10~100 倍但能治扫描件。便宜的先试，够用就停。
- **裁判标准统一为字符数阈值（≥20）而不是"是否报错"**——这是关键洞察：pypdf 对扫描件会**"成功"返回空串**，如果按异常判断就永远不会回退。"抽到了够用的字"才是真实的成功标准。
- **每级独立 try/except 置空继续**：任何一级崩溃都不阻断回退链。

OCR 级的三个工程细节（`extractors.py:90-109`）：

```python
        total = doc.page_count
        limit = min(total, _OCR_MAX_PAGES)      # 120 页上限
        matrix = fitz.Matrix(1.5, 1.5)          # 约 144dpi：速度与清晰度折中

```

1. **120 页上限**：OCR 单页约秒级，800 页扫描书会拖死队列。超出部分在文末注明"本次 OCR 仅处理前 120 页"——**把限制显式暴露给用户，而非静默截断**。
2. **引擎懒加载单例** `_get_ocr_engine()`：RapidOCR 初始化要加载 onnx 模型（数百 MB），绝不能每页 new 一次。
3. **1.5 倍缩放 ≈144dpi**：实测的速度/清晰度折中点。

### 第五步：网页——可选依赖的优雅写法

```python
# extractors.py:525-553
async def extract_webpage(url: str) -> str:
    async with httpx.AsyncClient(timeout=httpx.Timeout(20.0, connect=8.0), ...) as client:
        resp = await client.get(url)
        ctype = (resp.headers.get("content-type") or "").lower()
        if "html" not in ctype and "text" not in ctype:
            raise ValueError(f"链接不是网页正文（content-type={ctype}）")
        html = resp.text
    try:
        import trafilatura
        extracted = trafilatura.extract(html, include_comments=False, include_tables=False)
        if extracted and len(extracted.strip()) >= 40:
            return extracted.strip()
    except Exception:
        pass
    parser = _HTMLTextExtractor()   # 兜底
    ...
```

**两个教学点**：
- **content-type 前置检查**：避免把 PDF/zip 下载链接当 HTML 解析浪费一轮。
- **可选依赖的惯用手法**：`try import` 放在函数内。本项目所有重库（yt_dlp、fitz、ebooklib、rapidocr、trafilatura、faster_whisper）全部如此——**核心服务在缺少任一重依赖时仍能启动**，装了就增强。trafilatura 抽不到 40 字符就退回自写 parser，同一套裁判逻辑。

## 4. 完整流程图

```
process_extract 按 type 分派
 ├─ .txt/.md ──▶ decode_bytes（utf-8→utf-8-sig→gbk→gb18030→ignore）
 ├─ .epub ─────▶ ebooklib 解 zip → _HTMLTextExtractor 去标签（<20字报错）
 ├─ .pdf ──────▶ pypdf ─(不足20字)→ pymupdf ─(不足20字)→ RapidOCR(≤120页)
 └─ 网页 ──────▶ httpx 抓取(content-type 检查) → trafilatura ─(不足40字)→ 自写 parser
        │
        ▼  全部收敛
uploads/{id}/extracted.txt  →  status=ready
```
