# 技术框架文档（从零到一）

> 本篇不按"清单"罗列技术栈，而是回答一个问题：**如果让你从零做出「空库」，每一步会遇到什么问题、为什么会选中这个框架？**
> 按构建顺序分六层：后端骨架 → 数据层 → 文档/音视频解析 → AI 能力 → 前端 → 桌面端与工程化。

---

## 第一层：后端骨架——先让服务跑起来

### 问题 1：选什么 Web 框架？

需求：Python 生态（解析库丰富）、异步（IO 密集）、自带接口校验与文档。

**选择：FastAPI 0.115**（https://fastapi.tiangolo.com/）
- **在本项目的用途**：承载全部 REST API，11 个业务模块按 `router/service/schemas` 分层。
- **为什么是它**：类型注解即接口契约（pydantic 校验入参出参）；原生 async；自动生成 OpenAPI（喂给 Knife4j 出文档）；`BackgroundTasks` 提供零依赖的后台任务——喂养解析、对话生成全靠它。
- **使用要点**：应用组装在 `apps/api/app/main.py` 的 `create_app()`（详见 [功能点 01](./功能点/01-应用骨架与启动.md)）。

### 问题 2：ASGI 服务器？

**选择：Uvicorn 0.34**（https://www.uvicorn.org/）
- **用途**：运行 FastAPI 的 ASGI 服务器。开发 `uvicorn app.main:app --reload --port 18765`；打包态由 `run_sidecar.py` 内嵌调用。
- **为什么是它**：FastAPI 官方搭档，`[standard]` extras 带 uvloop/watchfiles，热重载开箱即用。

### 问题 3：配置怎么管理？

**选择：pydantic-settings 2.8**（https://docs.pydantic.dev/latest/concepts/pydantic_settings/）
- **用途**：`core/config.py` 声明全部配置字段，自动读 `.env` 与环境变量。
- **关键设计**：从 `__file__` 反推 .env 位置（cwd 不可控）；敏感字段默认空串，零配置开箱。

## 第二层：数据层——存哪、怎么连、怎么迁移

### 问题 4：ORM 与驱动？

**选择：SQLAlchemy 2.0 asyncio**（https://www.sqlalchemy.org/）+ **aiosqlite**（https://aiosqlite.omnilib.dev/）+ **asyncpg**（https://magicstack.github.io/asyncpg/）
- **用途**：全异步 ORM；SQLite 默认（aiosqlite），PostgreSQL 可选（asyncpg）。
- **为什么全异步**：FastAPI 是 async 框架，同步 ORM 会阻塞事件循环——一个慢查询拖住所有请求。
- **为什么双驱动**：个人版零依赖用文件库；进阶用户可热切自备 Postgres（见 [功能点 14](./功能点/14-数据库热切换.md)）。

### 问题 5：要向量数据库吗？

**选择：pgvector 仅探测，不依赖**（https://github.com/pgvector/pgvector）
- **本项目的取舍**：向量以 JSON 字符串存 `chunks.embedding` 文本列，检索用纯 Python 余弦相似度（`core/llm.py`）。千级切片规模下暴力扫描毫秒级完成，换来**零外部服务依赖**。pgvector 只探测扩展是否存在，为将来优化预留。

## 第三层：解析层——把各种格式变成纯文本

这一层是"喂养"能力的核心，每个库对应一种格式的具体问题（完整实现见 [功能点 04](./功能点/04-内容解析抽取.md)）。

| 库 | 官网 | 解决什么问题 | 在本项目的角色 |
|----|------|--------------|----------------|
| ebooklib 0.18 | https://github.com/aerkalov/ebooklib | EPUB = zip + XHTML，需要解包 | 解 EPUB 拿章节（去标签用标准库 HTMLParser，不引 BeautifulSoup） |
| pypdf 5.4 | https://pypdf.readthedocs.io/ | PDF 文字层抽取 | 第一级：快但弱 |
| PyMuPDF 1.25 | https://pymupdf.readthedocs.io/ | 更强的 PDF 文字层 + 页面渲染 | 第二级：文字层兜底；OCR 时把页面渲成图（144dpi） |
| RapidOCR 3.9 | https://github.com/RapidAI/RapidOCR | 扫描版 PDF 是图片，文字层为空 | 第三级：OCR 识别（中英，≤120 页） |
| onnxruntime | https://onnxruntime.ai/ | RapidOCR 的推理引擎 | 被 RapidOCR 依赖，加载 onnx 模型 |
| trafilatura 2.0 | https://trafilatura.readthedocs.io/ | 网页正文被导航/广告淹没 | 网页正文抽取（失败退回自写 parser） |
| Pillow / numpy | https://python-pillow.org/ | OCR 需要图像数组 | fitz 渲染结果 → numpy 数组喂给 RapidOCR |
| zhconv 1.4 | https://pypi.org/project/zhconv/ | 公版书/字幕可能是繁体 | 繁转简（可选增强，try 包裹） |

**统一手法**：所有重库都在函数内 `try import`——缺任何一个，核心服务照常启动，装了就有增强。

## 第四层：AI 与音视频——文案从哪来、答案怎么生

### 问题 6：LLM 怎么接？

**选择：httpx 直连 OpenAI 兼容接口**（https://www.python-httpx.org/；默认 DeepSeek https://platform.deepseek.com/）
- **为什么不引 LangChain 等框架**：全部需求就是 `/chat/completions` + `/embeddings` 两个 POST，一个 httpx 封装（`core/llm.py`）足矣。框架会带来版本地狱与黑盒。
- **关键设计**：凭据存 DB（设置页改 Key 立即生效）；embedding 失败返回 None 触发检索降级（见 [功能点 02](./功能点/02-模型与Key配置.md)、[08](./功能点/08-知识对话与拒答.md)）。

### 问题 7：视频文案怎么来？

**yt-dlp**（https://github.com/yt-dlp/yt-dlp）：拉字幕/元数据/音轨，支持抖音/B站/YouTube 等；**faster-whisper**（https://github.com/SYSTRAN/faster-whisper）：无字幕时本地语音转写（默认走 hf-mirror.com 镜像）；**imageio-ffmpeg**（https://github.com/imageio/imageio-ffmpeg）：内置 ffmpeg 二进制，用户机器不必装 ffmpeg。云端 ASR 走 OpenAI 兼容 `/audio/transcriptions`。详见 [功能点 05](./功能点/05-视频文案提取与ASR.md)。

## 第五层：前端——一套代码跑两种宿主

### 问题 8：UI 框架与构建？

**React 19**（https://react.dev/）+ **TypeScript 5.7**（https://www.typescriptlang.org/）+ **Vite 6**（https://vite.dev/）
- React：组件化 + hooks（项目无 Redux，状态全部走自定义 hooks）；
- Vite：dev 服务器 41779 端口 + 代理 `/api` 到后端（浏览器开发态零 CORS）；`base: "./"` 分支适配 Electron file:// 加载；`lazy` 路由切包防首屏卡。
- 详见 `apps/web/vite.config.ts` 与 [功能点 12](./功能点/12-桌面端Electron.md)。

### 问题 9：组件库？

**Ant Design 6**（https://ant.design/）：表单/表格/弹窗/消息全套，中文生态最熟。图标用 @ant-design/icons。

### 问题 10：笔记编辑器？

双编辑器策略（见 [功能点 09](./功能点/09-笔记库与双链.md)）：
- **TipTap 3**（https://tiptap.dev/）：Markdown 所见即所得，扩展生态（suggestion 做 Slash 命令与 `[[双链]]` 补全）；配 `marked`（MD→HTML）、`turndown`（HTML→MD）、`tippy.js`（浮层）。
- **yuque-editor-core**（语雀编辑器）：专业长文编辑，`.lake` 源文件；需 Vite 插件 `yuqueEnvAdapterPlugin` 给闭源包打补丁（transform 注入 envAdapter + optimizeDeps 排除）。

### 问题 11：前后端怎么约定接口？

无代码生成——`src/shared/api/client.ts` 一个 973 行的手写封装：`request<T>()` 统一处理 JSON/FormData/204/中文错误详情；`apiBase` 双宿主决策（Electron 走 preload 拿的 `apiOrigin`，浏览器空串走 Vite 代理）。

## 第六层：桌面端与工程化

### 问题 12：怎么变成桌面软件？

**Electron 35**（https://www.electronjs.org/）：主进程拉起 Python API（开发态 venv uvicorn / 打包态 sidecar）、开窗口、抖音桥、IPC。详见 [功能点 12](./功能点/12-桌面端Electron.md)。

### 问题 13：用户机器没有 Python？

**PyInstaller 6**（https://pyinstaller.org/）：把 FastAPI 打成单文件 sidecar（`apps/api/scripts/build_sidecar.py`），随安装包分发。

### 问题 14：怎么打包与更新？

**electron-builder 26**（https://www.electron.build/）：NSIS（Win，非一键可改目录）/ dmg+zip（Mac，zip 供增量更新）/ AppImage+deb（Linux）；**electron-updater** 走 GitHub Releases 自动更新；发版由 tag 触发 GitHub Actions 跨平台构建。

### 问题 15：API 文档给谁看？

**Knife4j**（https://doc.xiaominfo.com/）：`core/knife4j.py` 伪造 springdoc 协议（`/v3/api-docs`）复用其前端，访问 `/doc.html`。FastAPI 自带 docs 被关闭，避免双入口。

## 总览：选型背后的一条主线

| 层 | 技术 | 一句话理由 |
|----|------|------------|
| 后端 | FastAPI + Uvicorn + pydantic-settings | 异步 + 类型契约 + 零配置 |
| 数据 | SQLAlchemy asyncio + aiosqlite/asyncpg | 本地文件库起步，可热切 Postgres |
| 向量 | JSON 文本 + 纯 Python 余弦 | 零依赖，千级规模够用 |
| 解析 | ebooklib/pypdf/PyMuPDF/RapidOCR/trafilatura | 按格式成本递增回退 |
| 音视频 | yt-dlp / faster-whisper / imageio-ffmpeg | 字幕优先，ASR 兜底，ffmpeg 内置 |
| AI | httpx 直连 OpenAI 兼容（默认 DeepSeek） | 两个端点不需要框架 |
| 前端 | React 19 + Vite 6 + antd 6 + TipTap/语雀 | 一套代码两种宿主 |
| 桌面 | Electron + PyInstaller + electron-builder | 免环境、自动更新、反风控桥 |

**贯穿全部选型的哲学**：个人工具，部署零依赖优先于性能上限；每个外部依赖都有降级路径；每个失败都翻译成用户可执行的动作。
