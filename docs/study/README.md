## 一、这个项目是什么？

**「空库」是一个个人认知知识库应用**——一个"只信自己喂过的资料"的 AI 问答工具。

一句话概括：

> **空库起步 → 自己喂养电子书 / 笔记 / 视频链接（视频可自动提取文案）→ AI 自动总结归类 → 自备 API Key（如 DeepSeek）与知识库对话；对话只按库内资料作答，证据不足会拒答；资料可管理、可批注、可沉淀为笔记。**

它和普通的 ChatGPT/DeepSeek 对话最大的区别在于：**AI 不会凭自己的"常识"胡编**。它只能检索你喂进去的资料来回答；库里没有相关内容时，它会明确拒答，并标注每条回答的可信度（可信 / 存疑 / 冲突）和引用出处。

## 四、主要业务流程

### 1. 喂养 → 入库流程（核心）

```
用户投递（上传文件 / 粘贴笔记 / 贴链接）
        │
        ▼
   sources 队列（status: pending → extracting）
        │
        ▼
  内容解析（extractors.py）
   ├─ 电子书：TXT/MD 多编码解码、EPUB 解析
   ├─ PDF：pypdf → pymupdf → RapidOCR 三级回退
   ├─ 网页：trafilatura 抽正文
   └─ 视频：yt-dlp 拉字幕 → 无字幕走 ASR 转写
        │
        ▼
  统一产物 data/uploads/{id}/extracted.txt（status: ready）
        │
        ▼
  入库 ingest（classify.py）
   ├─ 有 Key：LLM 自动起标题、写摘要、分类
   ├─ 无 Key：启发式主题词归类
   └─ 去重指纹（title_key / content_hash）
        │
        ▼
  切片索引（chunking.py + index.py）
   按约 500 字切片（重叠 80）→ embedding → 存 chunks 表
        │
        ▼
   可被对话检索 / 知识浏览 / 批注
```

### 2. 对话问答流程（RAG + 拒答）

```
用户提问 → 受理落库（用户消息 + pending 占位，立即返回）
        │
        ▼
  后台检索（chat/service.py: _retrieve）
   ├─ 有 embedding：纯 Python 余弦相似度取 TopK（mode=vector）
   └─ 无 Key/向量失败：关键词打分降级（mode=keyword，标题加权 1.2）
        │
        ▼
  证据充分？ ──不足──▶ 拒答（refused=true，说明原因）
        │ 充分
        ▼
  LLM 生成 + 可信度尾巴 <<<TRUST:ok|suspect|conflict>>>
  （误拒答检测 → 强制重答一次）
        │
        ▼
  引用对齐（本地启发式 + 后台 AI 精修摘段）
        │
        ▼
  返回前端：答案 + 引用列表 + 可信度
  引用同时落为「对话预笔记」(chat_anchor)，用户确认后升级为正式笔记
```

### 3. 桌面端启动流程

```
npm run dev（apps/desktop）
   ├─ 复用或拉起 Vite 前端（41779）
   ├─ 启动 Electron 主进程
   │    ├─ 拉起 Python API（开发态 .venv uvicorn；打包态 PyInstaller sidecar）
   │    ├─ 端口治理：能力协商复用 / 杀掉旧孤儿进程
   │    ├─ 启动抖音桥（18766，应用内登录导出 Cookie 供 yt-dlp）
   │    └─ API 就绪后加载界面
   └─ 关闭窗口时停掉自己拉起的进程
```

## 五、贯穿全局的设计主线

读任何一篇功能点文档，都会反复遇到这三条哲学：

1. **零依赖优先**：SQLite 起步、JSON 存向量、BackgroundTasks 代替 Celery——个人工具不堆基础设施；
2. **每个外部依赖都有降级**：embedding 失败→关键词检索、LLM 失败→启发式归类、无字幕→ASR→补贴文案、yt-dlp 风控→桌面桥；
3. **每个失败都翻译成用户动作**：错误信息永远带"下一步该怎么办"。
