# 13 · 扩展：Skill 安装与市场

> **定位**：用 **类似 VS Code 扩展** 的方式安装、启用、卸载 Skill；先本地装包，后可选市场。  
> **前提**：自用闭环稳定后再开工；勿阻塞 [12](./12-扩展-云版多端与一键升级.md) 云版主线。  
> **红线**：Skill 只改「怎么用库」，不改「库里有什么」；事实结论仍只认库内检索 + [拒答](./03-拒答与质量.md)。

**一句话目标**：

> 用户像装 VS Code 插件一样装 Skill；装完改变喂养/对话/导出的**流程与格式**；没喂过的领域仍然拒答。附带材料须明确导入后才进入检索。

## 1. 和空库原则的边界（必须先对齐）

| | 知识库 | Skill |
|--|--------|--------|
| 本质 | **知道什么**（事实、材料、出处） | **怎么干**（步骤、规范、输出结构、工具编排） |
| 用户感知 | 喂书 → 能答；没喂 → 拒 | 安装流程包 → 按剧本工作 |
| 水源 | 已喂养切片 | 禁止当第二百科 |

### 1.1 硬规则

1. **事实结论的唯一水源** = 已喂养、已检索到的库内片段（见 [01](./01-知识库定位.md)、[03](./03-拒答与质量.md)）。  
2. Skill 可定义：提问结构、归类步骤、输出模板、拒答话术、导出格式。  
3. Skill **不可**在库无命中时用包内通识 / 模型通识补「领域答案」。  
4. 包内若带 `knowledge/`：安装时**可选导入喂养**；未导入 = 不进检索 = 相关问题仍拒答。

### 1.2 场景验收（中医 Skill 举例）

| 状态 | 用户问「肝肾阴虚用什么方？」 | 期望 |
|------|------------------------------|------|
| 已装中医 **流程** Skill，库内无中医材料 | **拒答**；可提示「可先喂相关书籍，或导入本包附带材料」 | |
| 同上，且用户确认导入了包内 `knowledge/` | 仅按**已入库切片**作答 + 引用；不足仍拒 | |
| 未装 Skill，但库内已喂《方剂学》等 | 按库内答（Skill 非必需） | |

**反模式**：安装「中医理论 Skill」后空库也能辨证开方 → 直接违背空库原则，禁止。

## 2. 对标 VS Code 的产品心智

| VS Code | 本产品 |
|---------|--------|
| `.vsix` / 扩展市场 | `.kongku-skill.zip` /（后）技能市场 |
| `package.json` | `skill.json` |
| 扩展代码与贡献点 | `SKILL.md` + 可选模板（首期不做任意可执行代码） |
| 扩展面板：安装 / 启用 / 卸载 | 「技能」页：同等交互 |
| 激活后改编辑器行为 | 启用后改对话流程 / 喂养编排 / 导出模板 |

用户主路径：

```text
打开「技能」→ 本地导入 zip（或以后从市场安装）→ 启用
  → 对话 / 喂养按已启用 Skill 工作
  → 事实仍走库内检索；无片段则拒答
```

## 3. 用户视角

| 步骤 | 使用者做什么 |
|------|--------------|
| 1 | 打开设置或侧栏「技能」 |
| 2 | 「从本地安装」选择 `.kongku-skill.zip`，或（L2）从市场一键安装 |
| 3 | 若包含附带材料：选择「仅装流程」或「同时导入知识库」 |
| 4 | 在列表中启用 / 禁用；可查看权限与版本 |
| 5 | 去对话或喂养：流程变化可见；库外题仍拒 |

卸载：移除包文件与启用状态；**已导入过的知识条目默认保留**（与卸载扩展后已改文件仍在类似），可提示「是否一并删除本次导入的条目」（可选，后置）。

## 4. 包格式（实现契约）

### 4.1 目录结构

```text
my-skill/
  skill.json          # 必填：清单
  SKILL.md            # 必填：给 Agent 的流程说明
  templates/          # 可选：输出 / 导出模板
  assets/icon.png     # 可选：图标
  knowledge/          # 可选：附带材料（默认不自动进检索）
  README.md           # 可选：给人看的说明
```

打包：上述根目录打成 **`{id}-{version}.kongku-skill.zip`**（扩展名也可用 `.zip`，以清单为准）。

### 4.2 `skill.json` 字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | 稳定标识，小写 + 连字符，如 `tcm-study-flow` |
| `name` | 是 | 展示名 |
| `version` | 是 | semver，如 `1.0.0` |
| `description` | 建议 | 一句话 |
| `type` | 是 | `workflow` \| `persona` \| `toolkit` |
| `entry` | 是 | 默认 `SKILL.md` |
| `permissions` | 是 | 权限白名单，见 §4.3 |
| `knowledge_policy` | 是 | 首期固定 **`library_only`** |
| `min_app_version` | 否 | 最低宿主版本 |
| `author` | 否 | 作者 |

示例：

```json
{
  "id": "tcm-study-flow",
  "name": "中医学习流程",
  "version": "1.0.0",
  "description": "按辨证结构组织提问与笔记整理；事实仍只认库内。",
  "type": "workflow",
  "entry": "SKILL.md",
  "permissions": ["chat.prompt", "feed.pipeline", "export.template"],
  "knowledge_policy": "library_only",
  "min_app_version": "0.1.0"
}
```

### 4.3 权限白名单（首期）

| 权限 | 含义 | 首期 |
|------|------|------|
| `chat.prompt` | 注入对话流程 / 输出结构（不注入事实） | 支持 |
| `feed.pipeline` | 介入喂养 / 归类检查清单或步骤提示 | 支持 |
| `export.template` | 提供导出模板 | 支持 |
| `tools.*` | 任意工具 / 脚本执行 | **不做** |

首期 Skill = **声明式 Markdown + 模板**，不跑第三方可执行代码（安全成本低于 VS Code 扩展宿主）。

### 4.4 `SKILL.md` 约定

- 写清：适用场景、步骤、输出格式、何时应拒答。  
- **禁止**写成长篇领域百科并暗示「无库也可答」。  
- 可写：「若检索无相关片段 → 明确拒答并提示喂养」。

## 5. 安装与存储

### 5.1 落地路径（个人版）

| 位置 | 用途 |
|------|------|
| `data/skills/<id>/` | 已安装包解压内容 |
| 库表或 `data/skills-state.json` | 启用状态、安装版本、安装时间、是否曾导入 knowledge |

云版自托管：同一逻辑，落在实例 `DATA_DIR/skills/`（与 [12](./12-扩展-云版多端与一键升级.md) 的数据根一致）。

### 5.2 安装流水线（L0）

```text
选择 zip
  → 校验：能解压、存在 skill.json + entry 文件、id/version 合法
  → 权限 ⊆ 白名单；knowledge_policy 必须为 library_only
  → 若 id 已存在：提示覆盖升级或取消
  → 解压到 data/skills/<id>/
  → 写入安装记录；默认启用（或默认禁用，产品二选一；建议「安装后默认启用」）
  → 若存在 knowledge/：弹窗「仅装流程」/「同时导入知识库」
```

### 5.3 启用时运行时行为

```text
用户发问 / 触发喂养
  → 加载全部「已启用」Skill 的 SKILL.md（及允许的模板）
  → 照常库内检索
  → 有片段：按 Skill 结构组织回答 + 引用
  → 无片段：拒答（Skill 不得补通识）
```

多 Skill 同时启用：按安装顺序或用户排序拼接；冲突时以更具体 workflow 优先（实现期可再定，文档先要求「可排序」）。

## 6. 能力分期（像插件一样，别一次做完市场）

### 6.1 L0 · 本地装包（先做）

| 能力 | DoD |
|------|-----|
| 导入 zip | 合法包装得上；非法包明确报错 |
| 列表 | 见已安装 id / 名称 / 版本 / 启用状态 |
| 启用 / 禁用 / 卸载 | 状态立刻影响下一轮对话 |
| knowledge 可选导入 | 未导入则库外仍拒；导入后可被检索 |
| 拒答回归 | 装领域 Skill + 空库 → 库外题必须拒 |

### 6.2 L1 · 技能管理页

| 能力 | DoD |
|------|-----|
| 独立「技能」页 | 安装入口 + 权限说明 + 包 README |
| 排序 | 多 Skill 时用户可调优先级 |
| 导出已装列表 | 可选：便于备份/迁移（后置也可） |

### 6.3 L2 · 市场（后置）

| 能力 | DoD |
|------|-----|
| 浏览 / 搜索 / 一键安装 | 体验接近扩展商店 |
| 更新检查 | 比对版本；签名或哈希校验 |
| 兼容第三方源 | 若同步类 SkillHub 包：安装后**仍强制**本产品 `library_only`，不原样放开「Skill 直接答题」 |

**明确不做（本阶段）**：Skill 内任意代码执行、自动静默改 Key、绕过实例口令。

## 7. 与 Agent / 知识编译的关系

| 概念 | 关系 |
|------|------|
| Skill | 可安装的流程与模板包（本文） |
| Agent | 编排层：选用哪些 Skill、何时检索、何时拒答；人格 ≠ 百科 |
| 知识编译 | 把库内材料整理成笔记/题卡等；输入必须来自库（或已导入的 knowledge） |

并行排期：可在 [12](./12-扩展-云版多端与一键升级.md) 的 B0 之后穿插 L0，**不得阻塞**「可云访问」主线。

## 8. 产品话术（对用户）

> 技能像编辑器插件：改变「怎么整理、怎么提问、怎么导出」。  
> 它不代替喂养。没进知识库的内容，对话仍然会拒绝回答。  
> 若技能包自带参考材料，只有你确认导入后，才会被检索引用。

拒单话术（市场/交付时）：

- 「装了就能当中医百科用」→ 不符合产品；应改为「装流程 + 自己喂书 / 可选导入包内材料」。

## 9. 推荐开工顺序（给你自己）

```text
S0  包格式 + 校验 + data/skills 落地
  → S1  启用状态接入对话提示词（library_only 闸门）
  → S2  技能页：安装 / 启用 / 卸载 + 中医流程样例包（无预置百科）
  → S3  knowledge/ 可选导入喂养
  → （过闸门后）S4 市场索引 + 更新 + 哈希校验
```

| 阶段 | 完成定义 |
|------|----------|
| S0 | 本地 zip 装进 `data/skills/<id>/`，坏包失败可解释 |
| S1 | 启用 Skill 后输出结构变化；空库库外题仍拒 |
| S2 | UI 可完成本地 zip 安装 / 启用 / 卸载全流程（不预置演示包） |
| S3 | 附带材料「导入 / 不导入」行为符合 §1.2 |
| S4 | 市场安装与本地安装同一运行时约束 |

### 9.1 自测题（Skill 专项）

| 题 | 期望 |
|----|------|
| 空库 + 启用样例 Skill，问库外事实 | 拒答 |
| 喂入相关笔记后再问 | 能答且有引用；格式可体现 Skill |
| 禁用 Skill 后再问 | 仍按库内答，但不再强制该 Skill 的结构 |
| 卸载 Skill | 列表消失；库内已有条目仍在（除非用户选了删除导入） |
| 恶意包：缺清单 / 超权限 / 可执行脚本 | 安装失败 |

## 10. 风险与对策

| 风险 | 对策 |
|------|------|
| Skill 变成预装百科 | `knowledge_policy=library_only`；验收 §1.2；市场审核拒「无库可答」包 |
| 第三方包投毒 / 泄 Key | 首期仅 Markdown；L2 要哈希/签名；权限白名单 |
| 多 Skill 提示词膨胀 | 限制同时启用数量或总字符；用户可排序/禁用 |
| 与云版数据目录不一致 | 统一挂在 `DATA_DIR/skills` |
| 拖垮自用认知主线 | 未过 [10](./10-扩展-市场与闸门.md) 不把 S4 市场当 KPI；L0/L1 可自用穿插 |
