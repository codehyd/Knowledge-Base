# 12 · 扩展：云版多端与一键升级

> **定位**：把「单机 Electron + 本机 API」拓展成 **可云部署、网页 / App / 小程序等不依赖本机服务** 的交付形态，并规划 **管理端一键升级前后端**。  
> **前提**：自用闭环稳定后再开工；闸门见 [10-扩展-市场与闸门](./10-扩展-市场与闸门.md)。  
> **相关**：[08-扩展-对外交付](./08-扩展-对外交付.md)、[工程/13-桌面端 Electron](../工程/13-桌面端Electron.md)、[工程/00-技术选型](../工程/00-技术选型.md)。

## 1. 三种视角（先对齐认知）

### 1.1 用户视角

> **与产品定位对齐**：空库是 **个人知识库 · 单实例**，**没有**「注册用户 / 管理员角色 / 多账号」体系（见 [01-知识库定位](./01-知识库定位.md)）。  
> 下文「使用者」= 买了并部署这一套的那个人；不是 SaaS 里的 User 表。

| 步骤 | 使用者做什么 |
|------|------------|
| 1 | 获得正版（激活码 / 下载权限） |
| 2 | 在**自己的**云或电脑上按文档安装 |
| 3 | （仅云版需要）设一个 **实例访问口令**，防止别人打开网址乱动你的库；再配置自己的 AI API Key |
| 4 | 电脑浏览器打开「自己的网址」；若设了口令，输入口令解锁本实例 |
| 5 | 手机浏览器打开**同一个网址**（同一口令） |
| 6 | 以后在设置里点「检查更新 / 一键升级」（可选能力） |

**口令 ≠ 用户体系**：本机 Electron 局域网自用可以继续「打开即用」；一旦 API 挂到公网/手机远程访问，需要一把锁，否则谁猜到网址谁就能喂养、导出、改 Key。这把锁是**整库访问保护**，不是「管理员账号 vs 普通用户」。

使用者感知：资料在自己机器上；AI 费用走自己的 Key；不依赖你家 NAS / 你家服务器。

### 1.2 你的视角（开发者 / 卖方）

| 你负责 | 你不负责 |
|--------|----------|
| 打出可部署包（镜像 / 静态资源 + API） | 给每个用户买云主机 |
| 安装与升级文档 | 替用户付模型 Token |
| （可选）许可证与更新通道 | 默认托管所有人的知识数据 |
| 修 bug、发版本 | 承诺绝对零停机（初期） |

类比：你造洗衣机 + 说明书 + 保修；水电是用户自己的。

### 1.3 设计视角（三块积木）

```text
① 使用界面          ② 知识库大脑              ③ 外部大模型
  Web / H5 /          （用户云上的闭源 API）      DeepSeek 等
  App / 小程序   ──▶  存资料 · 检索 · 对话   ──▶  用户自备 Key
  Electron 壳         以后：Skill / 编译
```

| 积木 | 含义 | 部署在哪 |
|------|------|----------|
| ① | 纯客户端，可连远程 | 浏览器 / 壳 / 小程序运行时 |
| ② | 业务与数据 | **用户自己的服务器**（或本机 Docker） |
| ③ | 推理 | 模型厂商；不经过你的业务大服务器（默认） |

**硬约束**：凡是「不能依赖本地服务」的端（公网手机、小程序、别人的电脑浏览器），**必须只依赖可达的 ②（公网或内网 HTTPS API）**，不能写死 `127.0.0.1`。

## 2. 现状 vs 目标

### 2.1 现状（个人版 · 单机）

参见 [工程/13-桌面端 Electron](../工程/13-桌面端Electron.md)、[04-工具与运行](./04-工具与运行.md)。

```text
打开 Electron
  → 自动拉起本机 Python API（localhost）
  → SQLite 在 ./data
  → 关闭 Electron 可结束其拉起的 API
```

| 能力 | 单机 Electron |
|------|----------------|
| 本机网页调试 | 可以（Vite + 手动 API） |
| 出门用手机访问家里库 | 默认不行（除非穿透，且常限速） |
| 交给别人「只打开网址就用」 | 不行 |
| 小程序 / 独立 App | 不行（依赖本机服务） |

### 2.2 目标（云版 · 自托管 B 方案）

```text
用户云主机：Docker 跑「API +（可选）托管前端静态资源」
        ↑ HTTPS
网页 / 手机 H5 / PWA /（后）App·小程序 / Electron 远程模式
```

| 能力 | 云版自托管 |
|------|------------|
| 网页端 | 同一套 React，配 API 地址；云版可加「实例口令解锁」 |
| 手机 | 先做响应式 Web / PWA；原生后置 |
| 小程序 | 后置；仍只调用户自托管 API（注意合法域名与 HTTPS） |
| Electron | 保留：本地一体 **或**「连接远程服务器」 |
| 升级 | 换镜像；可选设置页按钮触发（有口令则需先解锁） |

**明确不做（本阶段）**：你为所有用户免费提供长期业务云主机（那是「官方托管 A」，另定价、另闸门）。

## 3. 和「公司传统上云」的对照

你已有的心智模型可以直接复用：

| 公司常见做法 | 空库云版（B） |
|--------------|----------------|
| 前端打 `dist` | 前端构建静态资源 |
| 后端打 `.jar` | 后端打 **Docker 镜像**（或等价可执行产物；当前栈为 FastAPI） |
| 上传到**公司**云 + Nginx | 把同一套产物交给用户，上传到**用户**云 + Nginx/Caddy |
| 用户打开公司域名 | 用户打开**自己的**域名 |

只改一点：**部署对象从「你家云」变成「用户的云」。**

## 4. 目标架构

### 4.1 逻辑架构

```text
┌─────────────────────────────────────────────────────────┐
│ 客户端（①）                                              │
│  Web（主）· 手机浏览器/PWA · Electron 远程 · 后：App/小程序 │
└────────────────────────────┬────────────────────────────┘
                             │ HTTPS +（可选）实例口令 / 访问令牌
                             ▼
┌─────────────────────────────────────────────────────────┐
│ 用户云主机上的闭源服务（②）· 仍是单实例个人库，无多用户表   │
│  FastAPI · 静态 Web（可同容器）· 数据卷 data/              │
│  环境变量：LICENSE、PUBLIC_URL、DATA_DIR、ACCESS_PASSWORD… │
└────────────────────────────┬────────────────────────────┘
                             │ 出网
                             ▼
                    用户自备的模型 API（③）

（可选，你侧极轻量）
  许可证激活 / 版本检查 / 吊销 ── 不承载用户知识正文
```

### 4.2 与仓库目录的映射

| 现有 | 云版中的角色 |
|------|----------------|
| `apps/api` | ② 的主体；必须可脱离 Electron 独立进程 / 容器运行 |
| `apps/web` | ① 的主 UI；构建后由 API 或 Nginx 托管 |
| `apps/desktop` | ① 的可选壳；增加「远程 API Base URL」模式 |
| `data/` | 仅运行时卷；**不打进镜像** |
| 新建 `deploy/`（建议） | `Dockerfile`、`compose.yml`、Caddy/Nginx 示例、升级脚本 |

### 4.3 数据与密钥边界

| 内容 | 位置 |
|------|------|
| 书、笔记、切片、对话 | 用户 `data` 卷 |
| 用户 AI Key | 用户实例内配置（加密存储）；**不进你的许可服务** |
| 许可证公钥 / 版本清单 | 可进镜像或你的更新服务 |
| 你的源码 | 私有仓；对外交付镜像而非源码 zip（闭源） |

## 5. 从单机到云版：改造清单（工程）

### 5.1 阶段总表

| 阶段 | 名称 | 目标 | 依赖本地服务？ |
|------|------|------|----------------|
| **B0** | API 远程化 + 实例口令 | 任意浏览器连「已启动的 API」；公网须加锁 | 否（连远程即可） |
| **B1** | Docker 自托管包 | 用户云上一键起 | 否 |
| **B2** | 手机可用 Web | 小屏完整主路径 | 否 |
| **B3** | 许可证 + 私有镜像 | 可售卖的闭源交付 | 否 |
| **B4** | 管理端一键升级 | 按钮触发换版本 | 否 |
| **B5** | Electron 远程模式 / PWA | 桌面壳与「添加到主屏」 | 否 |
| **B6** | App / 小程序（后置） | 原生或双端壳 | 否（仍打用户 API） |

### 5.2 B0 · API 远程化与实例口令（地基）

**问题**：现在 UI 默认打本机；API 若暴露到公网且不加锁，等于把个人知识库敞开。

**不是要做的**：User 表、注册、角色（管理员/成员）、多人协作账号体系。  
**是要做的**：整实例一把「访问口令 / 访问令牌」——知道口令 ≈ 拥有整库（与当前单人产品一致）。

| 项 | 要求 |
|----|------|
| 独立启动 | `uvicorn` / sidecar 不依赖 Electron 父进程即可服务 |
| 监听 | 容器内 `0.0.0.0`；宿主机建议 `127.0.0.1` + 反代，或防火墙限制 |
| 配置 | `DATA_DIR`、`HOST`、`PORT`、`CORS_ORIGINS`、`PUBLIC_URL` |
| 实例口令 | 环境变量或首次设置写入本地配置；校验通过后发短期 token（Cookie/Header）；除 `/health`、解锁接口外均需带令牌 |
| 本机模式 | Electron / 仅 localhost 时可默认关闭口令（保持「打开即用」） |
| 前端 | 可配置 `API Base URL`；云版增加「输入口令解锁」屏（不是注册页） |
| CORS | 允许实际访问前端的 Origin |

**验收**：

- [ ] 机器 A 只跑 API；机器 B 浏览器打开前端，输入口令后能对话  
- [ ] 未解锁不能喂养 / 不能改设置 / 不能导出  
- [ ] 产品中仍无「用户列表 / 角色管理」类功能  
- [ ] 无 AI Key 时行为与现网一致（不能解析 / 不能对话）

### 5.3 B1 · Docker 自托管交付

| 项 | 要求 |
|----|------|
| 镜像 | 含 API + 前端静态资源（推荐同镜像，降低用户心智） |
| 卷 | `./data:/data`（库、上传、导出临时文件） |
| Compose | 单服务起步；文档给 Caddy/Nginx HTTPS 示例 |
| 环境变量 | 见 `.env.example`（无真实 Key、无你的私钥） |
| 文档 | 《30 分钟自托管跑通》：买机 → Docker → 拉镜像 → up → 域名 → 设实例口令 → AI Key → 样例喂养 |

**验收**：

- [ ] 空机器按文档能完成：能喂 / 能答 / 会拒  
- [ ] 删容器保留卷后重建，数据仍在  
- [ ] 镜像内无开发用 API Key、无用户样例隐私数据 |

### 5.4 B2 · 手机网页

| 项 | 要求 |
|----|------|
| 布局 | 侧栏改抽屉；对话区、上传区可单手操作 |
| 引导 | 首次可填服务器地址（若前端与 API 不同源时） |
| 长任务 | 解析 / 以后编译：进度可回看，不依赖「一直开着同一页」 |

**验收**：

- [ ] 手机 4G 打开使用者域名，输入口令解锁 → 喂一条 → 问一句  

**暂不做**：原生 App 上架、微信小程序（见 B6）。

### 5.5 B3 · 闭源与许可证

| 项 | 要求 |
|----|------|
| 分发 | 私有镜像仓库；正版账号可 pull |
| 许可证 | `LICENSE_KEY` 启动校验（本地验签）；可选在线心跳 |
| 协议 | 禁止二次分发镜像与破解；个人 / 商用 SKU 可分 |
| 更新源 | 版本清单 API 或仓库 tag；应用内「当前版本 / 最新版本」 |

**验收**：

- [ ] 无效许可证：拒绝启动或只读降级（产品需二选一定死）  
- [ ] 正版可 pull 指定版本 tag  

### 5.6 B5 · Electron 与远程模式

| 模式 | 行为 |
|------|------|
| 本地一体（现有） | 仍可 spawn 本机 API；适合纯个人、不上云 |
| 远程连接 | 不强制起本地 API；设置里填云版 Base URL +（若启用）实例口令 |

两者共享同一套 `apps/web` UI。

### 5.7 B6 · App / 小程序（后置说明）

| 端 | 要点 |
|----|------|
| App | 优先 WebView / PWA 壳，仍请求用户 API；注意证书与明文 HTTP 禁止 |
| 微信小程序 | **必须 HTTPS 合法域名**；域名是**用户的**时，每人域名不同 → 产品与合规成本高，建议：**很后做**，或只支持「官方托管 A」下的统一域名 |
| 策略建议 | 多端主路径定为 **响应式 Web + PWA**；小程序当作单独商业决策，不阻塞 B0～B4 |

## 6. 版本升级总方案（不含按钮时）

### 6.1 原则

```text
镜像可变（代码 + 前端 + 依赖）
data 卷不可丢（数据库 + 上传）
升级 = 换镜像 +（启动时）自动迁移
```

- **依赖升级**（Python 包等）：打进新镜像，禁止要求用户 SSH 上手动 `pip install`。  
- **前端升级**：新静态资源进同一新镜像（或同版本号的前端镜像），与后端版本号对齐。  
- **库表变更**：启动时自动 migrate（如 Alembic）；遵循「先加字段、后删字段」的兼容策略。

### 6.2 停机预期（对外话术）

| 级别 | 用户感受 | 本阶段态度 |
|------|----------|------------|
| 短暂停机（秒～约 1 分钟） | 刷新后恢复 | **默认承诺** |
| 近似零停机（蓝绿） | 几乎无感 | 可选增强 |
| 严格零停机（多副本） | 升级中也不断 | 需多实例；**默认 SQLite 不适合**，后置 |

初期文档写清：

> 升级过程通常很短，期间服务可能暂时不可用；知识数据在数据卷中，不会因换镜像而删除。

### 6.3 标准升级命令（用户侧）

```bash
docker compose pull
docker compose up -d
docker compose logs -f --tail=100
```

回滚：将镜像 tag 改回上一版本再 `up -d`（若迁移声明为不可逆，changelog 必须红字警告）。

### 6.4 给你写用户说明书的提纲

1. 备份：拷贝 `data/` 或停机打包卷  
2. pull 新版本  
3. up -d  
4. 看健康检查 / 日志中 migrate 成功  
5. 浏览器强制刷新（Ctrl+F5）

## 7. 前端按钮一键升级方案

### 7.1 产品定义

| 项 | 内容 |
|----|------|
| 入口 | 设置 → 关于 / 系统更新（须已通过实例口令解锁；本机无口令则打开即可见） |
| 能力 | 检查更新；展示当前版本 vs 最新版；确认后一键升级；看进度与结果 |
| 结果 | 同一版本镜像内前后端一起更新；完成后提示刷新 |

**使用者心智**：点按钮 ≈ 帮我在服务器上执行「官方升级步骤」。  
**不是**：浏览器单独热更新后端进程而不重启。  
**也不是**：多角色里的「管理员菜单」——单实例下，能解锁的人就能升级（升级前建议再确认一次口令或二次确认框）。

### 7.2 流程

```text
[检查更新]
  → GET 版本清单（你的更新服务或镜像仓库元数据）
  → 对比 local version vs latest
  → 展示 changelog（可选）

[确认升级]
  → POST /api/admin/system/update  { target_version }
  → 服务端进入 updating 状态（拒绝新的写业务或只读）
  → 执行升级脚本：docker pull → compose up -d
  → （进程会被替换；需「升级助手」或外部守护来做完 pull/up）

[升级后]
  → 新进程启动 → migrate → /health OK
  → 前端轮询健康或用户手动刷新
  → 提示「已是最新」
```

### 7.3 为何「纯 API 容器内自升级」会踩坑

API 若跑在将被替换的容器里：

- 容器执行 `docker compose up` 替换**自己**时，命令可能被杀中断；  
- 需要额外权限（Docker socket），攻击面大。

因此推荐两种实现档位：

#### 档位 U1 · 检查更新 + 复制命令（先做）

| 项 | 说明 |
|----|------|
| 按钮 | 「检查更新」「复制升级命令」「打开升级文档」 |
| 服务端 | 只读：返回当前版本、最新版本、changelog |
| 风险 | 低 |
| 停机 | 由用户在 SSH/面板执行命令时发生 |

**验收**：已解锁实例后，设置页能看到有新版本，并一键复制官方命令。

#### 档位 U2 · 一键升级（后做）

| 项 | 说明 |
|----|------|
| 组件 | **升级代理（update agent）** 与业务容器分离：agent 常驻，有权限 pull/up；业务容器无 Docker 权限 |
| 或 | 使用成熟方案（如 Watchtower）由接口「触发检查」；UI 只负责展示 |
| 保护 | 须已解锁实例 + 二次确认（可再输一次口令）+ 操作日志 |
| 状态机 | `idle → checking → downloading → restarting → healthy / failed` |
| 前端 | 进度条；`restarting` 时提示「请等待并刷新」；超时给出失败与回滚指引 |

**安全**：

- 未解锁不得调用升级接口  
- 不把 Docker socket 暴露给无保护的网络  
- 升级目标版本必须来自你签名的清单或允许的 tag 前缀，防任意镜像名注入  
- 仍无「普通用户 / 管理员」二分——单实例一把口令  

**验收**：

- [ ] 解锁后一点确认，无需 SSH，版本号变为目标版  
- [ ] 升级后 data 卷数据仍在，主路径可用  
- [ ] 未解锁返回 401/403  
- [ ] 失败时有明确错误，业务容器尽可能仍停留在旧版可运行状态 |

#### 档位 U3 · 自动更新（可选）

- 设置项：「有新版本时自动升级」默认 **关**  
- 仅建议活跃维护的个人实例；商用环境默认手动  

### 7.4 建议接口草案（U1 / U2）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/system/version` | 当前版本、构建时间、实例 id（匿名）；需已解锁（或仅本机） |
| GET | `/api/system/updates` | 最新版、强制/可选、changelog、最低可升级来源版本 |
| POST | `/api/system/update` | body: `{ "version": "1.4.0" }`；U1 可返回 `commands[]` 而不执行 |
| GET | `/api/system/update/status` | 当前升级状态机；供前端轮询 |

路径用 `system` 而非 `admin`，避免暗示多角色。  
健康检查：`GET /health` 保持**无需口令**（供反代与升级后探测）。

### 7.5 前端交互文案要点

- 检查中 / 已是最新 / 发现新版本  
- 确认框写明：**短暂不可用**、**请先备份 data（推荐）**  
- 升级中：不要关闭页面；若长时间无响应，稍后刷新或看服务器日志  
- 成功：请强制刷新浏览器  
- 失败：保留旧版说明 + 文档链接

## 9. 推荐开工顺序（给你自己的排期）

```text
B0 实例口令（云版）+ API Base
  → B1 Docker 文档跑通
  → B2 手机布局
  → B3 许可证 + 私有镜像
```

| 阶段 | 完成定义 |

## 10. 风险与对策

| 风险 | 对策 |
|------|------|
| 公网裸奔 API | B0 启用实例口令；HTTPS；能不暴露 0.0.0.0 就不暴露 |
| 一键升级权限过大 | U2 用独立 agent；须解锁 + 二次确认；版本白名单 |
| 误做成多用户系统 | 严格单实例；口令只保护整库，不做 User/Role |
| SQLite + 多实例 | 不承诺多副本零停机；企业高可用另开 Postgres 版 |
| 小程序域名 | 主路径用 Web；小程序等 A 或统一域名方案 |
| 用户不会 Docker | 文档 +（可选）付费代装；降低期望而非加你无限免费运维 |
| 盗版镜像 | 闭源仓库 + 许可证 + 更新绑定；法律条款；靠体验与更新节奏 |
