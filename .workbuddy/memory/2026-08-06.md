## 新功能方向：B站合集/分P 批量入库（已确认设计，待实现）
- 场景：用户要喂 124 集课程视频（BV1RR4y147uY 中医基础理论·潘毅）作为知识库根底。
- 现状缺口：sources 流水线一个链接=一个视频；extractors.py:509 playlist 只取第一集。
- 已确认的设计：
  1. 喂养页视频链接旁加开关「合集/分P：导入全部集数」，默认关（仅第 1 集）；检测到多集先弹确认卡片（显示集数/预估耗时）。
  2. 合集名 → 自动建同名分类，各分集 Entry 挂上去（复用 categories/entry_categories，对话可按分类限定检索）。
  3. 分集标题 = 合集名 + 分集名（yt-dlp entry.title，如 "p01 第1讲 中医基础理论绪论（一）"）；**排序按 P 数字排，不用零填充字符串**。
  4. 列表：知识条目靠分类收拢 + 现有分页；队列/长列表真卡再开 antd Table 的 virtual 属性，不提前上 react-window。
- 实测结论（本机 yt-dlp 已验证）：
  - 两种链接形态（带 spm/vd_source 参数的干净链接、整段分享文案）均可 → normalize_media_url 剥参数，parse_share_input 抽 URL。
  - flat 展开可得 124 集（?p=1..124），entry.title 需逐集再取。
  - **该视频无 CC/AI 字幕**（仅 danmaku），即使带 Cookie 也没有 → 必须走 ASR 路径；单集约 31 分钟，124 集 ≈ 62 小时音频。
  - 云端 ASR 有 24MB 上限，30 分钟音频需降采样到 16kHz 单声道才稳；本地 faster-whisper（base）CPU 约 1~3x 实时 → 挂机 20~60 小时。
- 下一步：用户确认后实现（后端合集展开 + 分类挂载；前端开关 + 确认卡片）。

## 合集批量入库已实现（同日）
- 后端：sources 表加 collection_title/episode_no（列迁移在 database.py `_ensure_source_book_columns`）；`extractors.probe_playlist_sync`（flat 展开，entries 保序）；端点 `POST /api/sources/url/probe`、`POST /api/sources/url/batch`（limit 试跑；按 source_uri 去重可续跑；BackgroundTasks 串行解析）；process_extract 视频分支对 episode_no>0 刷新真实分集标题；ingest 时挂「合集名」分类（linked_category_ids 防重复关联）；list_sources 上限 100→500。
- **关键修复**：normalize_media_url 的 bilibili 分支原本丢弃全部 query，会把 ?p=N 抹掉导致所有分集回落 P1——已改为保留 p 参数。
- 前端：client.ts 加 probeUrl/urlBatch + SourceItem.collection_title/episode_no；FeedPage 加「合集/分P：导入全部集数」开关（默认关、localStorage 记忆）+ 确认 Modal（先试前5集 / 全部导入 / 取消 + ASR 授权提示）。
- 冒烟（18767 端口独立实例，不动用户 18765 进程）：分享文案 probe → 124 集 ✓；batch limit=5 → 创建 5 条、episode 1-5、串行解析 ✓；分集进入 need_transcript 属预期——该视频无字幕 + B站匿名抓取 403（需 B站 Cookie）+ 未开「允许下载音轨」。测试数据已清理。
- 用户正式试跑前置条件：设置→AI 开「允许下载音轨到本机」；若持续 403，把 B站登录 Cookie 导出到 data/yt-dlp-cookies.txt（或 KONGKU_YTDLP_COOKIES）。

## 项目代码分析（不读 docs，直接读代码）
- 项目「空库 kongku」：本地优先个人知识库桌面应用
  - apps/api：FastAPI sidecar（pgvector/SQLite 双模，embedding+混合检索，RAG 拒答闸门，TRUST 标记质检）
  - apps/web：React/Vite 前端（feed/chat/knowledge/notes/settings/skills）
  - apps/desktop：Electron 壳，API 同源托管前端
- 入库管线：EPUB/PDF（含 RapidOCR 扫描件）/TXT/网页（trafilatura）/视频链接（yt-dlp + faster-whisper 本地转写，不依赖字幕，支持抖音）
- 特色：默认空库、只按库内作答证据不足拒答、BYO API Key、Obsidian 双链笔记 vault、可安装 skills 技能包（约束输出格式不作知识源）
- 用户问题：作为副业方向的售卖切入点 + 后续优化方案 → 已给出建议
